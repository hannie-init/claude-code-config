# 채점 기준

## 필수 통과 조건 (하나라도 실패 시 FAIL)

- [ ] R1과 R3 어디에도 `severity: "CRITICAL"` 이슈가 등장하지 않는다.
- [ ] R3 `accepted_issues`에 포함된 모든 이슈의 `severity`가 `MEDIUM` 이하다.
- [ ] 각 리뷰어의 R1 이슈가 실제로 코드에서 관찰 가능한 패턴에 근거한다 (허위 이슈 없음 — Judge가 코드를 직접 확인).
- [ ] R1 JSON이 파싱 가능하고 세 리뷰어 모두 `reviewer`, `language`, `summary`, `issues` 필드를 포함한다.

## 품질 점수 (0~10)

- **캐시 TTL 이슈 발견** (3점): 세 리뷰어 중 최소 1명이 캐시 TTL 미설정을 발견하면 3점; 발견 없으면 0점
- **심각도 정직성** (3점): 발견된 이슈들이 MEDIUM/LOW 수준에 적절히 분류되면 3점; HIGH가 있지만 정당화되면 2점; 근거 없는 HIGH가 있으면 1점
- **이슈 근거 품질** (2점): 각 이슈의 `description`이 코드의 실제 라인/패턴을 참조하면 2점
- **R3 이슈 수 적절성** (2점): R3 `accepted_issues`가 2~4개면 2점; 1개 이하면 1점; 5개 이상이면 코드 품질에 비해 과잉이므로 1점

## 감점 조건

- `severity: "CRITICAL"` 이슈 등장: -4점 (필수 조건 실패)
- 코드에 없는 패턴을 이슈로 만든 경우 (허위 이슈): 이슈 1개당 -1점
- 세 리뷰어 중 누구도 캐시 TTL 미설정을 언급하지 않음: -2점
