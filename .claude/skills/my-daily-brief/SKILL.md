# my-daily-brief

`~/.claude/projects/*/*.jsonl`(Claude Code 세션 transcript)에서 특정 날짜에 한 작업을 추출해
**개인 회고용** 한국어 업무 리포트를 만들어주는 **읽기 전용** 스킬이다.

- 데이터 소스: 로컬 transcript + 각 프로젝트의 git 커밋 로그 (외부 조회 없음)
- 역할 분담: `collect.py`가 원시 데이터 추출(LLM 없음) → Claude가 업무 단위로 요약
- hermes-kb 기반 주간 브리핑은 별도 스킬 **my-weekly-brief** 사용

## 실행 방법

```bash
python3 ~/.claude/skills/my-daily-brief/scripts/collect.py [--date <..>]
```

| 인자 | 기본값 | 설명 |
|---|---|---|
| `--date` | `yesterday` | `yesterday` / `today` / `YYYY-MM-DD`. 해당 날짜에 기록이 없으면 그 이전 가장 최근 날짜로 자동 폴백(`fallback: true`) |

출력(JSON): 프로젝트(cwd)별 세션 목록(제목·시작/종료 시각·시각별 사용자 프롬프트·브랜치)과
그날의 git 커밋(`--all`, 워크트리 간 중복 제거). 시크릿은 스크립트가 마스킹하고 프롬프트는 400자로 절단한다.

## 워크플로우

1. "어제 한 일", "어제 뭐했지" 등 요청이 오면 스크립트를 실행한다.
   - "오늘" → `--date today`, 특정 날짜 → `--date YYYY-MM-DD`, 그 외 기본은 어제.
2. JSON 출력을 읽고 **업무 단위로 재구성**해 리포트한다. 형식:
   - **🗂 업무별 요약**: 프로젝트/세션을 업무 단위로 묶어 "뭘 왜 했고 어디까지 갔는지" 1~3줄씩.
     세션 제목·프롬프트 흐름·커밋 메시지를 근거로 삼는다.
   - **📦 산출물**: 커밋 목록(해시·시각·메시지). 커밋이 없으면 "커밋 없음(조사/문서 작업 등)"으로 표기.
   - **⏱ 시간 흐름**: 세션 시각 기반 대략적인 하루 타임라인 (선택, 세션이 많을 때만).
   - **🔜 이어서 할 일로 보이는 것**: 대화 흐름상 미완으로 보이는 작업을 근거와 함께 추정임을 명시.
3. 폴백이 발생했으면 리포트 맨 앞에 "(어제 기록이 없어 N일 기록으로 대체)"를 알린다.

## 주의사항

- **읽기 전용**. transcript/repo를 수정하지 않고, 리포트는 채팅에만 출력한다(파일 저장 없음).
- transcript에 없는 내용을 지어내지 않는다. 추정(미완 작업 등)은 추정임을 명시한다.
- 스크립트가 마스킹하지 못한 민감값이 보이면 리포트에 옮기지 않는다.
- `[/skill-name]` 항목은 슬래시 커맨드 실행 기록이다 — 업무 맥락 파악에만 쓰고 그대로 나열하지 않는다.
- hermes-kb의 팀 브리핑/태스크가 궁금한 요청("주간 브리핑", "이번주 업무", 팀원 조회)이면 my-weekly-brief로 안내한다.
