# my-weekly-brief

`khc-dt/hermes-kb`(private) 지식베이스에 매일 쌓이는 **데일리 브리핑**과 **open-tasks**에서
특정 사람(기본: 하니, `hannie.init(김한나)`)의 업무를 **주간 단위로 집계**해 한국어로 보여주는
**읽기 전용** 스킬이다. `--date`를 주면 기존처럼 특정일 하루치만 조회할 수도 있다.

데이터는 hermes-worker 파이프라인이 생성한다. 이 스킬은 워커를 실행하지 않고, 이미 만들어진
KB 산출물만 `gh api`로 온디맨드 조회한다(로컬 클론·크레덴셜 불필요, `gh` 인증만 있으면 됨).

> 로컬 Claude Code 대화 기록 기반의 "어제/오늘 한 일" 리포트는 별도 스킬 **my-daily-brief**를 쓴다.

## 실행 방법

```bash
python3 ~/.claude/skills/my-weekly-brief/scripts/brief.py [--week <..>] [--date <..>] [--person <alias>] [--json]
```

| 인자 | 기본값 | 설명 |
|---|---|---|
| `--week` | (미지정) | `this`(이번주 월~일) / `last`(지난주) / `YYYY-MM-DD`(그 날짜가 속한 주). 미지정 시 **가장 최근 브리핑일 기준 최근 7일** |
| `--date` | (미지정) | 지정하면 주간 대신 **단일일 모드**: `latest` / `today` / `yesterday` / `YYYY-MM-DD`. 없는 날짜는 그 이하 최신으로 폴백 |
| `--person` | `hannie.init` | 영문 alias. `hannie.init(김한나)` 처럼 줘도 됨. 예: `kane.cho` |
| `--json` | (off) | 필터된 원본 JSON 출력 |

환경변수: `HERMES_KB_REPO`(기본 `khc-dt/hermes-kb`), `HERMES_ME`(기본 `hannie.init`)로 override 가능.

## 워크플로우

1. "이번주 업무", "주간 브리핑" 등으로 요청하면 스크립트를 실행한다.
   - "이번주" → `--week this`, "지난주" → `--week last`, 언급 없으면 인자 없이(최근 7일).
   - "9월 16일 브리핑"처럼 특정일 요청 → `--date YYYY-MM-DD` 단일일 모드.
   - 특정 팀원 언급(예: "기호님 주간 브리핑") → `--person kane.cho` 처럼 영문 alias로 매핑.
2. 스크립트 출력을 그대로 보여주되, 주간 모드에서는 앞에 **주간 요약 2~3줄**(주요 진행 축, 완료 건수, 블로커 유무)을 붙인다.
3. 출처(`source_refs`)와 지라 링크는 그대로 유지해 근거를 남긴다.

## 출력 해석

- **주간 모드**: 날짜별 섹션(`[MM-DD 요일]`)에 그날의 🔵 진행/예정(`action_items`) · ✅ 완료(`done_items`) · ⚠️ 블로커(`blockers`)를 있는 것만 표시. 마지막에 📌 미완료 태스크를 1회 표시.
- **단일일 모드**: 기존 데일리 포맷(🔵/✅/⚠️/📌) 그대로.
- `[상/중/하]`는 중요도, 없으면 `[ ]`.
- **📌 미완료 태스크**: `open-tasks.json`에서 내 `owner`이고 `status != done`인 것. 마감일 있는 것·우선순위 높은 것 우선 정렬.
- 브리핑 스키마는 날짜에 따라 항목이 문자열이거나 객체일 수 있으며 스크립트가 둘 다 처리한다.

## 주의사항

- **읽기 전용**. hermes-kb는 파이프라인 산출물이라 사람이 수정하지 않는다. 이 스킬은 조회만 한다.
- KB에 없는 내용을 지어내지 않는다. 항목이 없으면 "(없음)"으로 표시된 그대로 전달한다.
- 데이터 신선도는 워커의 마지막 실행 시점에 달려 있다. 최신 날짜가 오래됐으면 그 사실을 언급한다.
