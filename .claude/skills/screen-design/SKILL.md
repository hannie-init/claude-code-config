# Screen Design Workflow

신규 화면 기획 또는 기존 화면 UX 개선을 **상의 → 확정 → 기획서** 순으로 진행한다. 핵심 원칙:

- **바로 구현하지 않는다.** 결정 지점이 남아 있으면 먼저 사용자와 확정한다.
- **기존 패턴 우선.** 새 스타일·라이브러리 도입 없이 프로젝트의 기존 화면 톤을 따른다.
- 탐색·설계는 **ui-designer 에이전트**에 위임하고, 사용자 질문은 **메인이 AskUserQuestion**으로 한다(서브에이전트는 질문 불가).

## 모드 판별

- 신규 화면/기능 기획, "화면 구성 정하자" → **기획 모드** (1~5단계)
- "UI 리뷰", 기존 화면 UX 점검 → **리뷰 모드** (아래 별도)

---

## 기획 모드

### 1. 요구 수집

다음이 파악될 때까지 확인한다 (부족하면 AskUserQuestion, 한 번에 2~3개까지만):

- **화면 목적·사용자**: 누가(CS/기획/개발/외부), 어떤 업무 흐름에서 쓰는가
- **데이터 소스**: API 스펙 존재 여부·확정 상태. 스펙이 별도 문서(Notion/Google Sheets/엑셀)에 있으면 **먼저 가져와 읽고** 화면 기획과의 차이(필드·enum·에러 코드)를 짚는다
- **유사 화면**: 참고할 기존 화면이 있는지 (사용자가 스크린샷을 주면 그 톤을 기준으로)
- **메뉴 위치**: nav 어디에 들어가는가

⚠️ 스펙 문서와 실제 API가 다를 수 있다(요청서 vs 구현). 어느 쪽이 최신인지 확인하고, 차이는 표로 정리해 사용자에게 보고한다.

### 2. 컨텍스트 탐색 + 초안 설계 (ui-designer 위임)

`Agent(subagent_type: "ui-designer")`로 위임한다. 프롬프트에 반드시 포함:

- 1단계에서 수집한 요구·API 스펙 전문
- 대상 프로젝트 경로와 "기존 패턴 탐색 → 재사용 목록 → 초안 설계 → 결정 지점 목록 반환" 지시
- 읽기 전용(코드 수정 금지) 명시

에이전트 반환물: 레이아웃 목업 / 컴포넌트 재사용 계획 / 상태별 UX / **결정 지점 목록(질문·옵션·추천·preview 포함)**.

### 3. 상의 루프 (메인이 AskUserQuestion)

- 에이전트가 반환한 결정 지점을 **AskUserQuestion**으로 확정한다. 옵션에 ASCII preview를 붙이고, **추천안을 첫 번째**에 배치한다.
- **한 번에 최대 2~3개**만 질문한다. 앞 질문의 답이 뒤 질문을 바꾸면 나눠서.
- 사용자가 옵션 차이를 되물으면: 표 + 옵션별 목업 + 사용 흐름 비교로 **재설명한 뒤** 다시 질문한다.
- 사용자가 스펙을 정정하면(필드 변경, enum 개편 등) 기획서에 즉시 반영하고, 기존 결정과 충돌하는지 확인한다.

### 4. 확정 기획서 산출

- 확정본을 대화에 정리한다: 레이아웃 목업(최종) / 컴포넌트 구성 / 상태별 UX / enum 라벨 / 검증 UX / 미해결 항목(백엔드 확인 필요 등).
- **프로젝트 메모리**(`project_*.md`)에 확정 사항을 기록한다 — 다음 세션 연속성용.
- 별도 기획서 파일 저장은 사용자가 원할 때만.

### 5. 다음 단계 안내 (제안만)

구현 위임(서브에이전트) / 커밋·PR / Figma 작업 여부를 **제안만 하고** 사용자 선택을 기다린다. 임의로 구현을 시작하지 않는다.

## 리뷰 모드

1. 리뷰 대상(화면 디렉토리·파일)을 특정한다.
2. `Agent(subagent_type: "ui-designer")`에 리뷰 모드로 위임 — 대상 경로와 "판정 기준표 형식 리포트 반환, 읽기 전용" 명시.
3. 반환된 리포트(🔴/🟡 + `file:line` 근거 + 처방)를 사용자에게 전달하고, 수정할 항목을 고르게 한다. **수정도 사용자 선택 후에만** 진행.
